# Gemma4 Independent Golden Logits

`gemma4_reference.json` is generated by the unmodified official PyPI
`transformers==5.19.0` implementation, `Gemma4ForCausalLM`, running with
`torch==2.8.0+cpu`, Python 3.12, Linux x86_64. No pretrained model, tokenizer,
remote code, or Candle output is used. All persistent weights and layer-scalar
buffers are replaced deterministically before inference. Nonpersistent RoPE and
embedding-scale buffers are constructed by Transformers itself.

Upstream source:
<https://github.com/huggingface/transformers/tree/v5.19.0/src/transformers/models/gemma4>

## Regeneration

From the repository root (installation needs network; generation does not):

```sh
ls /tmp/opencode
python3.12 -m venv /tmp/opencode/gemma4-reference-venv
/tmp/opencode/gemma4-reference-venv/bin/pip install -r candle-transformers/tests/gemma4_reference_requirements.txt
/tmp/opencode/gemma4-reference-venv/bin/python candle-transformers/tests/gemma4_reference.py
```

The generator asserts the numerical-library versions, runs CPU float32 eager
attention with one thread, deterministic algorithms, eval and inference mode,
and disables Hub access. It emits the adjacent JSON file. The requirements pin
the full installed dependency set. Torch 2.6.0 CPU was tried but failed during
Transformers' accelerator detection; no compatibility monkeypatch was used.

The Rust test uses `include_str!` and requires neither Python nor Hugging Face:

```sh
/home/opencode/.cargo/bin/cargo test --locked --offline -p candle-transformers --test gemma4_tests
```

## Coverage

- Tiny two-layer dense text configuration matches `gemma4_tests.rs::config()`;
  PLE, cross-layer KV sharing, MoE, and double-wide MLP are disabled explicitly.
- The wrapping-u32 relative-name weight algorithm matches `weights()` with
  float32 rounding at each arithmetic operation. Learned RMS weights are
  nonuniform and nonunit, testing direct weights rather than Gemma3's `1 + w`.
- Local attention has four Q heads, two KV heads, head dimension four, window
  three; global attention has four Q heads and head dimension eight. With K=V
  it has one KV head without a V projection; without K=V it has two KV heads
  and separate K/V projections. HF supplies the normalization, unit attention
  scaling, rotary calculation, masking, cache, GELU, residuals, and softcap.
- Four cases: tied head, untied head, tied head with half-dimensional
  proportional RoPE (theta 100 for both layers) and negative layer scalars.
  The third exercises a nontrivial frequency exponent and nonrotated channels,
  and makes scalar signs observable despite the final RMS normalization.
  The fourth has a tied head, K=V disabled, and a conflicting global KV-head
  override, regression-testing that the override is ignored in this mode.
  The original three fixture cases are unchanged.
- Each case stores all 16 logits for fresh prefix lengths 1 through 9 and,
  separately, actual HF cached runs with prefill lengths 1, 2, 4, and 7 followed
  by single tokens through length 9. This crosses the local window repeatedly
  and tests prefill both below and above the window. HF cached/fresh agreement
  is checked before writing, but cached goldens are not copied from fresh rows.
- Rust checks both checkpoint prefixes against these same independent logits,
  using absolute tolerance `2e-5`, zero relative tolerance, and finite checks.
  There are 4,480 scalar logit comparisons (4 cases, 35 rows, 16 logits,
  2 checkpoint prefixes). The original self-consistency tests are retained.

This is numerical verification of the supported tiny dense CPU/F32 subset,
not validation of real model checkpoints, multimodal execution, PLE, MoE,
shared-KV consumers, reduced precision, GPU/FlashAttention, or cached chunks.
It does not claim that every accepted configuration matches upstream semantics.

## Global KV Override Regression

`separate_kv_ignores_global_override` sets `attention_k_eq_v=false`,
`num_key_value_heads=2`, and `num_global_key_value_heads=1`. Official Transformers
5.19.0 ignores the global override when K=V is disabled. Both the generator and
Rust test assert that global K and V weights have shape `[16, 8]`, not `[8, 8]`.
The Rust helper supplies a separate deterministic V projection for this case.
This guards against the previous unconditional override, which would reject
these HF-shaped weights during loading.

With the corrected production selection, all 35 HF logit rows for this case
pass for both checkpoint prefixes: 1,120 new scalar comparisons covering fresh
prefills and cached single-token decoding across the local window. The full
offline integration suite passes: 6 passed, 0 failed, 0 ignored. No production
files were edited while adding this regression coverage.
